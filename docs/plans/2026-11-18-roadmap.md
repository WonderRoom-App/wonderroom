# WonderRoom roadmap

**Spec:** `docs/specs/2026-11-18-wonderroom-design.md`

The spec covers several subsystems. Each milestone below gets its own detailed plan, written
when the milestone before it is done. Results from early milestones (above all M0) change how
later ones are built, so detailed plans for later milestones would go stale.

Each milestone ends with something that runs and a check that proves it.

| # | Milestone | Done when |
|---|---|---|
| M0 | **Migrations test build** (throwaway) | A findings doc answers the spec's three migration questions, and the spec's Migrations section names the chosen approach. |
| M1 | **Engine core**: npm workspaces, the Next.js + Payload app, `definePlugin`, `requires` ordering, the item type registry, the core item fields, reading `plugins.yml` and `config.d`, migrations at start (from M0) | A toy item type plugin listed in `plugins.yml` gets its tables at start and appears in the admin. A missing `requires` or a loop stops the start with a clear message. |
| M2 | **Public pages and privacy**: the item service (public path and owner path), engine route folders, the plugin route table and catch-all, core Pages, the two-pass leak check | The toy item has a public page. A private field never shows as a visitor. The owner path returns nothing for a visitor. A Pages row renders at its slug. |
| M3 | **Admin sections**: the label-only tabs, placing fields by section name | A plugin field appears in the section it names. Adding the tabs renames no column. |
| M4 | **DT plugins**: Makers, Condition, YouTube, Typewriters, Calculators, Marvels, then Blog, Highlights, Featured, Recommendations, then eBay and TWDB | Each plugin runs on the engine with DT's dev data, and its own tests pass. |
| M5 | **Core layout and skin**: DT's layout as the core layout, every color and font as a CSS variable, the "typed on paper" skin as settings | DT's pages look the same as v0.50.0 with the skin loaded. A changed color in `config.d` shows after a restart, with no build. |
| M6 | **Image and start sequence**: the prebuilt first-party image, the start script, the shipped `docker-compose.yml` | A fresh droplet-sized VM (2 GB with swap) starts the site from the compose file and a config folder. Measure the real build memory here. |
| M7 | **DT on WonderRoom**: DT's config folder, the one-way data migration, the parity check | A copy of DT's live data runs on the engine, and a page-by-page check against v0.50.0 shows no visible change. |
